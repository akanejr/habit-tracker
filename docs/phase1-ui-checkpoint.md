# Phase 1 UI implementation checkpoint — not a release

This is a work-in-progress checkpoint, **not a declaration that Phase 1 or Bloom is complete**. The normal `/dashboard` still uses the legacy day-log implementation. The session workspace and new browser-only demo are not integrated with an approved session backend. The complete database, secure deletion, recovery and final integration remain future phases; none of the SQL experiments is a production migration.

## Local-only UX work

`/bloom-phase1` is disabled unless `BLOOM_PHASE1_DEMO=1`. When enabled, it renders the sessions workspace with a typed browser-local adapter and a persistent, visible simulation warning. It does not send demo commands to Supabase. Synthetic data is saved in that browser's localStorage and may be cleared from Settings; it is not synced, secured, server-authoritative, production-grade or safe for real data. Its timestamps and goal effective week use the browser clock only to demonstrate interactions; they do **not** implement or validate the actual-commit requirement. Its localStorage operations do not establish cross-tab concurrency or real durability.

The sandbox implements habit create/edit/archive and history; timer start/pause/resume/complete/cancel with a four-hour continue option; quick logs, backdating and multiple daily entries; simulated target/no-target confirmation and history; weekly counts, active days, separated and combined duration reporting; simulated profile, theme and reset; and loading, error, pending retry, offline, success and maintenance messaging. Unresolved goal state does not hide the independently calculated counts. Existing auth routes remain separate, and account deletion is deliberately unavailable. The older `/bloom-local` route retains its own separate local-Supabase adapter and safeguards.

Changes to session workspace reuse existing code but do not make the legacy `/dashboard` use sessions. Real authentication, local Supabase RPC integration for the combined design, mobile OS sleep/locking behavior, real multi-device timer recovery, accessibility beyond limited automated scans, and end-to-end service/security/data-integrity behavior have not been certified by this checkpoint. No hosted data was inspected or written. No app can be deemed deployable from these tests.

## Actual tests performed

- In a disposable source copy without `.env*`, Node 22: `npm run typecheck`, `npm run lint`, 10 existing `session-core` unit tests, and a Next.js production build passed. The source copy used an independent copy of existing dependencies, not hosted credentials.
- `tests/phase1-demo.browser.mjs` passed Chromium at 390px/dark and 1440px/light: create/edit/archive, target 12 and No target, start/pause/resume/complete, Quick Log while running, past and future-date handling, known-name history, navigation, reload, offline pause message, simulated profile/theme, reports, empty state, an initial axe scan, no horizontal overflow and no external browser requests. A separate scenario checked simulated five-hour warning/continue, multiple quick logs, cancel exclusion, unknown durations, reopen using browser storage, and counts with a deliberately unresolved goal. These are simulated UI tests, not real database or real-device proofs.
- `tests/session-ui.mock.mjs` passed with an intercepted in-memory PostgREST mock, including simulated SQLSTATE 55000 maintenance, same-request retry, intentional response loss (the 400 and 503 console responses are injected test events), offline, timer, history and archive. It used the test-only fixture in a disposable copy, never in the application tree.
- `tests/phase1-auth.mock.mjs` passed intercepted synthetic invalid-login, password mismatch, unverified signup, password recovery, resend and invalid reset-link UI checks. It is not a Supabase Auth security test.
- With the demo environment flag absent, `/bloom-phase1` returned HTTP 404 in the local test. Automated axe coverage was only the initial screen in each viewport; it does not establish full accessibility.

## Reproduction notes

Use a disposable source copy that excludes `.env*`, `.git` and `.next`; install/copy the repository's existing dependencies there. Use Node 22. For demo tests, run `BLOOM_PHASE1_DEMO=1 node node_modules/next/dist/bin/next start -H 0.0.0.0 -p 3103` after building, then `node tests/phase1-demo.browser.mjs`. For intercepted Auth and older session tests, put the test fixture into `app/bloom-harness/page.tsx` **only in the disposable copy**, build/start with `NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321` and a synthetic anon value on port 3100, then run `tests/session-ui.mock.mjs` and `tests/phase1-auth.mock.mjs`. Browser requests to that loopback URL are intercepted; do not substitute a hosted URL or credentials. The test fixture must never be shipped. Chromium and its OS libraries are required.
